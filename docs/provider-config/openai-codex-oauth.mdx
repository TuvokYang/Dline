title: "OpenAI Codex Profile OAuth"
description: "使用浏览器 OAuth 或手工 JSON 导入为每个 OpenAI Codex Profile 建立独立凭据。"
---

OpenAI Codex 使用 ChatGPT 订阅账户的 OAuth 授权。每个 Dline API Profile 都是独立的凭据所有者；一个 Profile 的登录、刷新、退出或删除不会复用或修改另一个 Profile 的凭据。

## OAUTH 认证

1. 打开 Dline 设置并进入 **API Configuration**。
2. 新建或展开一个 Provider 为 **ChatGPT Subscription** 的 Profile。
3. 点击 **开始 OAUTH 认证**。
4. Dline 会立即打开OAUTH认证模态，先启动本地callback server，再按实际监听端口生成认证URI并尝试打开系统浏览器。
5. 模态会显示认证URI、复制按钮、重新打开浏览器按钮、超时倒计时和完整callback URI兜底；不会单独显示callback listener地址。
6. 在浏览器中完成授权。自动localhost callback成功后，模态会自动关闭，Profile显示 **已认证**。

认证URI只属于当前活动flow，可能包含state和最终`redirect_uri`。不要把它保存到Profile、日志或普通设置中。若浏览器未能自动打开，可复制该URI并手工粘贴到浏览器。

如果需要使用多个 Codex Profile，请分别展开每个 Profile 并完成一次登录。即使多个 Profile 使用同一个 OpenAI 账户，它们仍拥有彼此隔离的凭据文件和运行时会话。

## Callback URI 兜底

浏览器无法自动回到Dline时，可以在当前OAUTH认证模态内使用手工兜底：

1. 保持OAUTH认证模态打开，不要取消流程。
2. 从浏览器地址栏复制授权完成后的**完整localhost callback URI**。
3. 将完整URI粘贴到 **完整回调 URI**。
4. 点击模态最底部的 **完成认证**。成功后模态自动关闭。

该 URI 必须属于当前仍在进行的 Profile 登录流程，并包含匹配的 callback 地址、授权码和 state。Dline 不会把 callback URI 保存到 Profile。

Callback URI 兜底只接受当前浏览器流程产生的完整 URI；不要在该输入框中粘贴 OAuth JSON、token 或单独的授权码。

## 手工导入完整 OAuth JSON

OAUTH认证仍是首选方式。如果已有完整OAuth credential JSON，请先打开目标Profile的OAUTH认证模态，再展开 **高级：导入 OAuth credential JSON**，粘贴完整JSON并点击 **导入凭据**。该高级输入默认折叠，textarea高度受限且只在展开时挂载。

- `access_token` 和毫秒时间戳 `expires` 必填；
- `refresh_token` 可选，提供时必须是非空字符串；
- JSON 必须整体通过解析和凭据校验后才会原子替换该 Profile 的旧凭据；
- 解析、校验或保存失败不会修改旧凭据；
- 提交、失败、取消、关闭模态、切换 Profile 或组件卸载后，输入框中的敏感文本都会被清除。

没有`refresh_token`的凭据在access token有效期内可以正常使用。过期、强制刷新或服务端返回HTTP 401后，Dline不会调用refresh endpoint，而是只将该Profile标记为需要重新认证；其他Profile不受影响。

Dline不提供手工Refresh按钮，也不运行固定的后台刷新定时器。未过期时直接使用；过期且有refresh token时，在下一次请求前自动single-flight refresh；HTTP 401时force refresh并只重试一次。

## 超时与端口

每个OAUTH认证flow默认有效五分钟。模态显示后端提供的倒计时；超时后旧URI输入被清空并禁用，界面显示认证超时并提供 **重新认证**。重新认证会生成新的flow ID、state、PKCE verifier和认证URI，旧callback不能复用。

端口占用时，Dline只能在OpenAI认可的callback端口候选中切换，并在最终端口监听成功后生成认证URI。未经Provider批准的随机端口不会用于生产认证；如果所有批准端口均不可用，Dline会停止并给出可操作错误，而不会生成注定被OpenAI拒绝的redirect URI。

## 凭据存储

每个 Profile 的 OAuth 凭据保存在独立文件中：

```text
data/secrets/openai_codex_<profile-id-sha256-prefix>.json
```

文件名使用 Profile 稳定 ID 的 SHA-256 前 32 个十六进制字符，而不是 Profile 显示名称。因此：

- 重命名 Profile 不会改变或丢失凭据；
- 不同 Profile 不会共享同一个 OAuth 文件；
- Dline 发起请求时，Bearer token 与 `ChatGPT-Account-Id` 来自同一份 Profile 凭据快照；
- Codex 不读取、写入、迁移或创建废弃的 `data/secrets.json`。

不要手工复制、合并或编辑这些文件。需要更换账户时，请使用Profile中的 **重新进行 OAUTH 认证**；完整JSON导入只作为认证模态内的高级恢复入口。

## 旧凭据迁移

升级后，Dline 会按现有 Codex Profile 数量安全处理旧的单文件凭据：

- **只有一个 Codex Profile**：旧凭据可以迁移为该 Profile 独占的凭据文件；
- **存在多个 Codex Profile**：Dline 不会猜测凭据归属，也不会把可轮换的 refresh token 复制到多个 Profile。相关 Profile 会要求分别重新登录；
- 损坏或无法确认归属的旧数据不会被静默当作有效凭据使用。

迁移完成后，每个 Profile 仍必须满足“一份 Profile 身份对应一份 OAuth 文件”的规则。

## Profile 生命周期

以下操作只影响目标 Profile：

- **退出认证**：删除该Profile的OAuth凭据；
- **Delete Profile**：删除该 Profile 及其 OAuth 凭据；
- **切换到其他 Provider**：清理该 Profile 原有的 Codex OAuth 凭据；
- **Rename、修改模型、推理设置或启用状态**：保留该 Profile 的 OAuth 凭据；
- **重新进行 OAUTH 认证**：用新授权原子替换该Profile的旧凭据。

多个 VS Code 窗口共享同一 Dline 数据目录时，同一时间只允许一个本地 OAuth flow 持有跨进程 lease。其他窗口不能抢占、取消或覆盖当前窗口正在进行的授权。

## 安全说明

- OAuth URL、callback URI、授权码、state、JWT 和 token 不应出现在 Dline 日志、Profile Catalog、通知或普通状态消息中；
- 本地 callback server 只监听 loopback 地址，并校验 callback URI、PKCE 和 state；
- 有 refresh token 时，access token 刷新只更新所属 Profile；没有 refresh token 或刷新失败需要重新登录时，也只使该 Profile 失效；
- 请勿将 `data/secrets/openai_codex_*.json` 提交到版本控制、上传到工单或发送给他人。
