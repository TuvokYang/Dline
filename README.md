## 简介

Dline 是 [Cline](https://github.com/cline/cline) 的社区分支，长期运行在真实生产项目中。

在保留原有交互模型的前提下，Dline 对任务运行时、状态存储、提示词架构、上下文管理与终端执行等核心模块进行了大量重构，累计改动超过 2300 个源码文件、新增 30 万行代码。重构的主线是**任务隔离**：单个工作区内可以同时运行多个互不干扰的任务，每个任务拥有独立的 Profile、能力配置、检查点边界与执行状态。

适用的典型场景：

- 在一个工作区内同时推进多个任务，各自使用不同的模型与配置
- 让调研任务跑轻量模型、实现任务跑强模型，按任务而非全局绑定
- 按项目和任务分别启用技能、工作流与 MCP，而不是全局统一开关
- 处理容易超出上下文窗口的长任务，依靠多轮自动压缩持续执行
- 在长对话与频繁命令执行的工作流中保持界面与终端响应

## 安装

从源码构建 VSIX 并安装：

```bash
npm run install:all
npm run vsix
```

生成的 `.vsix` 可通过 VS Code 的「从 VSIX 安装扩展」加载，或执行：

```bash
code --install-extension <生成的-vsix-文件>
```

要求 VS Code 1.134.0 及以上版本。首次启动时，已有的 Cline 数据会自动迁移，过程不会破坏原数据。

## 核心能力

### 任务独立与并行执行

单个工作区内可并行运行多个任务，彼此完全隔离：

- **独立 Profile** — 每个任务任意绑定自己的模型与端点，调研任务用轻量模型、实现任务用强模型，互不影响
- **独立能力配置** — 技能、工作流、MCP、浏览器等能力按任务单独开关，并随任务持久化
- **独立检查点边界** — 文件归属按任务仲裁，检查点锁按任务分离，一个任务的回退不会波及另一个任务改动的文件
- **独立执行状态** — 取消、恢复、审批各自成链，不会相互串扰

### 多任务下的资源约束

并行任务共享同一台机器，因此代码搜索与状态写入都有明确的配额和调度策略：

- **搜索 CPU 配额** — 单个任务的 ripgrep 进程最多占用 30% 逻辑线程，所有任务合计不超过 50%，避免一次全库搜索打满 CPU
- **写入去抖与批量落盘** — 状态变更先进内存缓存，去抖后批量写盘，避免高频写入拖慢交互
- **任务历史非阻塞写入** — 历史元数据写入排队后立即返回，事务在后台结算，UI 不等待磁盘
- **增量追加** — 会话消息按增量追加写入，避免每次落盘都重新序列化整个历史
- **检查点锁分离** — 检查点按任务持有独立锁，一个任务的保存不会阻塞另一个任务

### 能力三域分离配置

规则、技能、工作流、MCP 与浏览器等能力支持 **全局 / 工作区 / 任务** 三层作用域，逐层覆盖：

| 作用域 | 适用场景 |
|---|---|
| 全局 | 所有项目通用的个人偏好 |
| 工作区 | 当前项目的团队约定 |
| 任务 | 本次任务临时启用或关闭 |

任务级设置随任务一起保存，恢复任务时自动还原，不会污染工作区配置。

### 迭代式自动压缩

上下文接近或超出窗口时，压缩会分多轮推进：每轮规划一段可安全压缩的对话范围，生成累积摘要并携带到下一轮，直到剩余上下文足以继续执行任务为止。

单轮压缩装不下的超长任务不会就此中断——压缩带有预算约束与重试重放，中途失败可以恢复并继续，而不是从头开始。

### 多 Profile 与服务商支持

同时管理多组 API 密钥与端点，按任务、子代理、图像生成等用途分别绑定。apiKey 存放在独立的密钥库中，与 Profile 配置解耦。切换 Profile 不会影响正在运行的其他任务。

支持 OpenAI、Anthropic、Gemini、DeepSeek、OpenRouter、AWS Bedrock、Qwen、GLM 等 30 余家服务商。模型支持多协议时，可自行选择 OpenAI Chat、OpenAI Responses 或 Anthropic Chat 格式。

### Web 搜索与抓取：本地与托管自动选择

`web_search` 与 `web_fetch` 会依据当前模型的能力自动路由：模型自带托管搜索时走服务商侧执行，否则回退到本地实现，无需手动切换。

也可以按 Profile 强制指定：自动、强制本地、强制托管或完全关闭。

### 图像生成

`generate_image` 支持三种来源：沿用当前 OpenAI Profile、使用服务商托管图像能力，或绑定独立的 OpenAI / Gemini 图像 Profile。可控制数量、尺寸、质量、格式与背景，并支持基于已有图像继续编辑。

### 对话消息增量式渲染

消息通过增量推送与虚拟滚动窗口渲染，只加载与绘制视口内的内容。对话长度增长时，滚动与输入保持流畅，不会随历史累积而变慢。

### 多终端热备启动

终端按配置分区预热待命实例，命令下发时直接取用已就绪的终端，省去 shell 启动与集成握手的等待。终端可复用、按需回收，并在异常时自动回退到冷启动。

### 实时活动面板

Work 与 Activities 双标签，让智能体的工作过程完全可见：正在执行的工具、子代理的调用时间线与指标、API 速率与上下文占用曲线、失败重试的完整过程。

### 子代理与任务编排

- `use_subagent` / `use_subagents` — 委派独立的只读调研任务，支持后台运行、超时控制与失败自动重试，一次最多并行 5 个
- `spawn_task` — 派生独立的对等任务，可指定以 Plan 或 Act 模式启动
- `load_skill` / `load_workflow` / `load_mcp` — 按需加载技能、工作流与 MCP 工具，不预先占用上下文

### 代码理解与修改

在常规的读写、搜索、命令执行之外，还提供基于 LSP 的语义工具：`find_references` 查找符号的全部引用，`rename` 执行语义级重命名，`replace_text` 跨文件批量替换。

### 终端与命令控制

命令可指定 `workdirectory` 而无需拼接 `cd`，可配置执行超时与后台交接时长，长时间运行的命令会转入后台并保留输出。`kill_command` 可终止指定命令。Windows 下自动处理 PowerShell 与 UTF-8 编码。

### 细粒度权限控制

`.agentignore` 支持按维度授权，而不只是简单的隐藏：

```gitignore
secrets/          # 移除全部权限
vendor/ -w        # 只读，禁止写入
generated/ -s     # 不出现在列表和搜索中，但可按路径读取
scripts/ext/ -x   # 禁止作为命令工作目录
```

能力开关支持全局、工作区、任务三层作用域覆盖，任务级设置会随任务一起持久化。

### 会话存储

任务历史存储在 SQLite 中，避免全量扫描。任务运行期间可继续输入，消息会排队并在安全边界送达。基于 Git 的检查点让你随时回退文件改动。

### 富文本渲染

对话中的 ` ```latex ` 代码块经 MathJax v4 排版为公式，` ```mermaid ` 渲染为图表并可导出 SVG。

### 可选的运行时诊断

遇到问题时，可在设置中开启运行时遥测采样，并一键导出诊断包。导出的 ZIP 不包含任何代码、提示词或凭据。该功能默认关闭。

## 配置目录

| 路径 | 用途 |
|---|---|
| `.agents/rules/` | 项目规则 |
| `.agents/workflows/` | 可复用的多步骤流程 |
| `.agents/skills/` | 任务专用方法与最佳实践 |
| `.agents/subagents/` | 子代理定义（YAML） |
| `.agentignore` | 智能体访问权限规则 |
| `.dline/mcp/` | MCP 服务器配置 |
